# Развёртывание TurnstileConnector в Docker

Внутренний сервер: Ubuntu 24.04, Docker 29, IP `192.168.100.41`.
Один контейнер = один процесс: FastAPI/Swagger + фоновый опрос контроллеров и ночная
сверка. Снаружи сервиса доступен через nginx: `/turnstile → 127.0.0.1:8002`.

Состояние коннектора живёт в базе (`turnstile_db`), поэтому **volume для данных не нужен** —
контейнер можно сносить и пересоздавать без потерь. Логи идут в stdout (`docker logs`).

---

## 1. Перед запуском (проверки)

На сервере `192.168.100.41`:

```bash
# Контроллеры пингуются (IP — из таблицы turnstile_controllers / config)
ping -c2 192.168.140.22
ping -c2 192.168.140.13

# База доступна с сервера
nc -zv 192.168.100.XX 3306      # XX — IP сервера базы ISU
```

> **Важно:** если раньше коннектор крутился как служба на Windows — **остановите её**.
> Иначе два экземпляра будут параллельно опрашивать контроллеры и дублировать проходы.

База должна быть подготовлена (один раз, не из контейнера):

```bash
mysql < turnstile_connector.sql    # база turnstile_db + таблицы
mysql < turnstile_view.sql         # вьюхи, тянущие источник из базы ISU
```

## 2. Настройка окружения

```bash
cp .env.example .env
nano .env                          # заполнить DB_*, API_KEY, HTTP_TOKEN; DRY_RUN=true на первый раз
```

`.env` в git и в образ **не попадает** (см. `.gitignore` / `.dockerignore`) — пароли только в нём.

Ключевые переменные:

| Переменная          | Зачем |
|---------------------|-------|
| `DB_*`              | подключение к базе (`turnstile_db`) |
| `DRY_RUN`           | `true` на первый запуск — на контроллеры ничего не шлётся, только лог |
| `API_KEY`           | ключ `X-API-Key` для эндпоинтов записи; пусто ⇒ запись выключена целиком |
| `UVICORN_ROOT_PATH` | `/turnstile` — префикс, который срезает nginx; Swagger будет на `/turnstile/docs` |
| `EVENTS_ENABLED`    | опрос проходов; включать после приёмки синхронизации карт |

---

## 3. Сборка образа

```bash
docker build -t turnstile:latest .
```

Базовый образ `python:3.12-slim` тянется через `mirror.gcr.io` (прописано в `Dockerfile`).

---

## 4. Запуск

```bash
docker run -d --name turnstile \
  --restart unless-stopped \
  --memory 512m \
  --env-file .env \
  -p 127.0.0.1:8002:8000 \
  turnstile:latest
```

- `-p 127.0.0.1:8002:8000` — порт контейнера `8000` публикуется **только на localhost** сервера,
  порт `8002`. Снаружи напрямую сервис недоступен — только через nginx.
- `--memory 512m` — потолок памяти.
- `--restart unless-stopped` — Docker сам поднимет контейнер после краша или ребута
  (внутри процесс при фатальной ошибке фонового потока делает `exit`, чтобы Docker перезапустил).

### Почему bridge + проброс порта, а не `--network host`

Коннектор общается с контроллерами по короткому протоколу **запрос-ответ по UDP**: сам
шлёт пакет и читает ответ с того же сокета. Контроллеры **ничего не пушат** и не шлют
широковещалку, которую надо ловить. Поэтому обычной bridge-сети с исходящим UDP достаточно —
ответы возвращаются по тому же соединению через NAT. `--network host` нужен был бы только
если бы надо было слушать входящие/броадкаст пакеты на интерфейсе хоста; здесь это не так,
а host-сеть лишь убрала бы изоляцию контейнера. Входящий HTTP тоже не требует host-сети —
достаточно пробросить один порт на localhost.

## 5. Проверка

```bash

# ждём: {"status":"ok","db":true,"controllers":[{"sn":...,"alive":true}, ...]}
```

Swagger (через nginx, см. ниже): `https://<хост>/turnstile/docs`

Логи:

```bash
docker logs -f turnstile
```

## 6. nginx (на хосте)

```nginx
location /turnstile/ {
    allow 192.168.100.0/24;        # только внутренняя сеть
    deny all;                      # эндпоинты записи наружу не торчат

    proxy_pass http://127.0.0.1:8002/;   # слэш в конце срезает префикс /turnstile
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

Два уровня защиты записи: **nginx** ограничивает по IP (`allow/deny`), приложение требует
**`X-API-Key`** (переменная `API_KEY`). Если `API_KEY` пуст — запись отключена целиком, открыт
только `GET /health`.

После правки конфига: `nginx -t && systemctl reload nginx`.

---

## 7. Обновление

```bash
git pull
docker build -t turnstile:latest .
docker rm -f turnstile
docker run -d --name turnstile --restart unless-stopped --memory 512m \
  --env-file .env -p 127.0.0.1:8002:8000 turnstile:latest
```

Данные в базе — пересоздание контейнера их не трогает.

---

## 8. Ввод в эксплуатацию (порядок)

1. `DRY_RUN=true`, `EVENTS_ENABLED=false` → запустить, смотреть `docker logs`: что коннектор
   *собирался бы* записать на контроллеры.
2. Убедились, что список карт верный → `DRY_RUN=false`, пересоздать контейнер → карты
   заливаются на контроллеры.
3. После приёмки синхронизации карт → `EVENTS_ENABLED=true` (+ при необходимости `MDB_PATH`
   для суточной сверки проходов), пересоздать контейнер.
